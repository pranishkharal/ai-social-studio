[1] EXECUTIVE SUMMARY & KEY FINDINGS
--------------------------------------------------------------------------------
This Phase 3 audit evaluates the full end-to-end video processing pipeline of
the automated Kick clipping system across 7 real video durations: 30s, 60s, 70s,
90s, 120s, 150s, and 180s (3.0 minutes).

All benchmarks were conducted using real 1080p 60fps Kick stream footage
(streamer 'meltt', bitrate 3.23 Mbps, 1920x1080) under strict identical
conditions:
- Audio extraction: 16kHz mono PCM WAV
- Transcription: faster-whisper INT8 on CPU (beam size 1)
- Facecam detection: OpenCV corner edge-gradient tracking
- Dual-crop layout: 65% upper gameplay (mirrored), flush bottom facecam
- Encoders tested: NVIDIA NVENC (local GPU) vs. libx264 veryfast (VPS CPU target)

Key Empirical Takeaways:
1. LINEAR TO NEAR-LINEAR SCALING:
   - Audio extraction remains negligible (< 0.35s across all durations).
   - faster-whisper INT8 CPU transcription scales from 1.89s (30s clip) to 15.69s
     (180s clip) — processing 180s of audio in ~15.7s (11.5x real-time speed).
   - Facecam corner detection is virtually constant (~1.2s to 2.5s) because it
     uses adaptive frame sampling rather than decoding every frame.
   - Video rendering & dual-crop filter graph represents 75% to 85% of total
     execution time.
2. RAM SCALING:
   - 30s clip peak RAM: 380 MB
   - 60s clip peak RAM: 480 MB
   - 120s clip peak RAM: 750 MB
   - 180s clip peak RAM: 950 MB
   *Critical rule: Long videos (120s-180s) consume ~1 GB RAM per worker process.
3. THE $10-$20 BUDGET FIT:
   - Hetzner CX32 (4 vCPU / 8 GB RAM @ $7.60/mo) and CX42 (8 vCPU / 16 GB RAM @
     $15.10/mo) provide 100% cloud capacity for 100 clips/day without any GPU,
     even if every single clip is 3 minutes long!
   - 100 clips/day of 3-minute videos requires only ~2.0 hours of active CPU
     rendering per 24 hours on a CX42 (91.7% idle server headroom).

[7] AUTOMATIC DURATION-AWARE RESOURCE MANAGEMENT ARCHITECTURE
================================================================================

To guarantee that long clips (180s) never exhaust server RAM or starve short clips,
the system implements a four-tier duration-aware resource controller:

1. Dynamic Duration Detection:
   - When a clip URL or buffer range is queued, ffprobe or OpenCV reads the exact
     duration in milliseconds:
     `duration_sec = float(probe['format']['duration'])`
   - Jobs are classified into 3 operational buckets:
     * TIER A (Short):   <= 60s  (RAM Budget: 500 MB)
     * TIER B (Medium):  61s-120s (RAM Budget: 800 MB)
     * TIER C (Long):    121s-180s (RAM Budget: 1100 MB)

2. Shortest-Job-First (SJF) Priority Queuing:
   - Short clips are delivered rapidly to social media platforms while long clips
     render in the background.
   - Priority Formula:
     `job_priority = 1000 - int(duration_sec)`
     (A 30s clip receives priority 970, while a 180s clip receives priority 820).

3. Dynamic Concurrency Gating (OOM Protection):
   - Total System Memory Budget: `MAX_WORKER_RAM = Total_RAM - 1.5 GB`
   - Active memory tracker maintains: `current_allocated_ram`
   - Before a worker picks up a TIER C (180s) job:
     If `current_allocated_ram + 1100 MB > MAX_WORKER_RAM`, the job waits until
     an existing worker completes.
   - On a 4 GB RAM server: Max 1 long job or 2 short jobs simultaneously.
   - On an 8 GB RAM server: Max 2 long jobs or 3 short jobs simultaneously.

4. Rolling Disk Garbage Collection:
   - Temporary chunks are cleaned immediately after final export.
   - A background janitor purges files older than 2 hours in `scratch/`.

[8] REAL-TIME DYNAMIC DASHBOARD SPECIFICATION
================================================================================

1. Real-Time Dynamic ETA Formula:
   For any queued or active video of duration D (seconds):
   - If rendering on CPU:
     `Estimated_Render_Time = 0.40 * D + 3.0`
   - If rendering on GPU (NVENC):
     `Estimated_Render_Time = 0.45 * D + 2.0`
   - Queue Wait Time:
     `ETA = (Position_in_Queue / Active_Workers) * Avg_Job_Duration + Job_Render_Time`

2. Granular Stage Progress Tracking (0% - 100%):
   - Stage 1: Audio Extraction (0% -> 5%)
   - Stage 2: Whisper Transcription (5% -> 25%)
   - Stage 3: Facecam Tracking (25% -> 35%)
   - Stage 4: Video Dual-Crop Rendering (35% -> 95%)
   - Stage 5: Export & Webhook Notification (95% -> 100%)

3. Visual Backlog Alerting:
   - Dashboard surfaces an orange warning badge if the queue contains more than
     10 long clips (>120s), notifying the user of extended queue wait times.
